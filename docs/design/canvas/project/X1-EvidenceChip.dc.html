Kontrakt danych

GET incidents/{id}/matches

Chip = jeden element evidence[] z GET /api/v1/incidents/{id}/matches (dla każdego kandydata). Szuflada dociąga GET /api/v1/evidence/values/{type}/{value}.

// incidents/{id}/matches → matches[].evidence[]
{
  "type": "kit",            // tracking|kit|infra|content|persons|visual|ad|media
  "field": "tracking.kit_endpoints",
  "value": "/api/v2/relay/lead/{uuid}/",
  "display": "relay/lead",   // skrót do UI
  "strength": "H",          // H|M|L (log m/u)
  "weight": 2.7,           // siła × rzadkość lub SHAP
  "shap": 2.7,
  "df": 58, "N": 1284, "idf": 3.10,
  "state": "match",        // match|conflict|missing|zero
  "sides": { "a": "INC-24817", "b": "KMP-017" }
}

Zasady

  • Tak: zawsze etykieta typu tekstem; kolor tylko ją wzmacnia.
  • Tak: sortuj po |wadze| malejąco, pokaż do 6 chipów, reszta jako „+3 więcej”.
  • Tak: skracaj wartość tylko w UI; w tooltipie, szufladzie i eksportach pełna wartość.
  • Nie: nie pokazuj wartości powszechnych (CDN, jquery, gstatic) jako dowodu; stan zero tylko w rozwiniętym „dlaczego”.
  • Nie: nie rysuj braków jak konfliktów: missing ma przerywaną ramkę i nie ma wagi.
