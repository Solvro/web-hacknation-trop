Śledztwo Agenta Smitha od jednej domeny

AktorAnalityk prowadzi, Agent Smith (LLM + narzędzia OSINT) wykonuje
Wyzwalacz„Śledź z agentem” w S05 albo omnibox: śledź velmoria.click
CelZnaleźć infrastrukturę, nowe domeny i reklamy kampanii; każde twierdzenie poparte wywołaniem narzędzia
Czas trwania~2 min · budżet 20 kroków

Sukces: 14 domen dołączonych do KMP-017, 3 certyfikaty z dzisiejszej nocy, 11 domen poza listą CERT PL gotowych do zgłoszenia. Każde ustalenie ma przypis do kroku agenta.

Ścieżka główna

seed: velmoria.click · KMP-017
1

Konfiguracja

10 s
Ekran: S07 · start śledztwa

Analityk: seed velmoria.click; budżet 20 kroków i 60k tokenów; narzędzia: crt.sh, DNS, RDAP, urlscan, Ad Library, CERT PL, Wayback, nasz indeks; tryb online lub cache.

POST /investigations {seed, budget, tools, mode}

2

Start i plan

3 s
Ekran: S07 · kanwa + case file

System: na kanwie pojawia się węzeł seed, a case file zaczyna od planu: „1. certyfikaty, 2. DNS, 3. ścieżka kitu…”.

GET /investigations/{id} · SSE /investigations/{id}/stream

3

Pivoty na żywo

~90 s
Ekran: S07 · graf rośnie

System: każdy krok dodaje węzły i krawędzie oraz akapit case file z przypisem. Szczegóły pivotów w tabeli poniżej.

SSE agent.step · graph.node_added · graph.edge_added · casefile.delta

4

Sterowanie

dowolnie
Ekran: S07 · pole „Wskazówka”

Analityk: „Sprawdź też domeny .live z tej samej partii certów”, „pomiń Wayback”, albo pauza / stop.

System: wskazówka staje się krokiem planu, z przypisem „na prośbę analityka”.

POST /investigations/{id}/steer {message} · POST /investigations/{id}/stop

5

Przegląd ustaleń

~1 min
Ekran: S07 · case file

Analityk: zaznacza ustalenia do przyjęcia; każde ma przypis: krok #, narzędzie, zapytanie, wynik, czas.

System: 3 certy wydane dziś w nocy; Oracle oznaczyła 2 z nich wcześniej.

GET /investigations/{id} → {findings[], tool_calls[]}

6

Promocja do kampanii

2 s
Ekran: S05 · KMP-017

Analityk: „Dodaj 14 domen do KMP-017”.

System: tworzy wskaźniki i incydenty z source=hunter, przelicza DNA; licznik domen rośnie z 19 do 33.

POST /investigations/{id}/promote {finding_ids, campaign_id} · SSE campaign.updated

7

Act: CERT PL

~1 min
Ekran: S10 · zgłoszenie CERT PL

System: formularz CERT PL wypełniony 11 domenami spoza listy, z dowodem dla każdej. Dalej jak w F2: potwierdzenie i wysyłka.

POST /act/packages {kind:"certpl", campaign_id, domains}

Stany brzegowe

jak UI je pokazuje
urlscan 429

Krok ma stan „czeka 30 s” z licznikiem. Agent przełącza się na nasz indeks, a log mówi to wprost.

Budżet wyczerpany

Agent kończy podsumowaniem „co zostało niesprawdzone”. Przycisk „+10 kroków” wymaga potwierdzenia analityka.

Strażnik halucynacji

Twierdzenie bez wywołania narzędzia jest szare i przekreślone, z etykietą „brak źródła”. Nie da się go promować.

Brak klucza LLM

Deterministyczny tryb pivotów w stałej kolejności (crt.sh → DNS → urlscan po kicie → Ad Library → CERT PL). Case file jako tabela, bez narracji.

Tryb offline

Narzędzia odpowiadają z cache, każdy wynik ma etykietę „cache 20.11”. Graf i case file działają tak samo.

Bezpieczeństwo

Agent nie odwiedza stron sam: odwiedziny idą przez worker capture w sandboxie, bez wysyłania formularzy. Lista narzędzi jest zamknięta.

Kryteria akceptacji

Graf rośnie na żywo; każdy węzeł ma źródło (numer kroku).

Case file jest strumieniowany; każde zdanie ma przypis do wywołania narzędzia.

Analityk może w każdej chwili wstrzymać, sterować i zatrzymać.

Promowane są tylko ustalenia zaznaczone przez analityka; zostaje wpis w logu audytu.

Budżet i koszt są widoczne: kroki, tokeny, czas.

Działa bez klucza LLM (tryb deterministyczny) i offline (cache).

Implementacja: kanwa React Flow sterowana zdarzeniami graph.*; case file to markdown z węzłami cytowań [#krok], renderowany przyrostowo z casefile.delta.
