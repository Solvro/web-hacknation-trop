Stany brzegowe

jak UI je pokazuje
Duplikaty L0

Pakiet deduplikuje reklamy po ID z Ad Library: 46 incydentów daje 58 unikalnych reklam. Licznik pokazuje obie liczby.

Reklama już usunięta

Oznaczona „już nieaktywna” i zachowana jako dowód kontekstu, ale nie trafia do listy żądań usunięcia.

Słaby członek

Pokrycie < 0.5 lub wynik < 0.6: domyślnie odznaczony w pakiecie, z adnotacją. Analityk może go dołączyć świadomie.

Brak ID reklamy

Materiał tylko ze zrzutu: zgłoszenie po URL landingu i zrzucie, z etykietą „bez ID z Ad Library”.

Platforma odrzuca

Status „odrzucone” z powodem. Przycisk „Uzupełnij i wyślij ponownie” tworzy nową wersję pakietu z historią.

Brak klucza LLM

Uzasadnienie z deterministycznego szablonu (lista dowodów i liczności), bez generowanego tekstu.

Dane osobowe w dowodach

Automatyczna redakcja numerów telefonów, IBAN i e-maili ofiar w zrzutach i tekstach przed eksportem; podgląd pokazuje zakryte pola.

Kryteria akceptacji

Pakiet obejmuje całą kampanię: wszystkie aktywne reklamy, reklamodawców i domeny, po deduplikacji.

Każda pozycja ma dowód (chip z odnośnikiem do incydentu) i zrzut.

Wysyłka wymaga jawnego potwierdzenia i zostawia wpis w logu audytu.

Podgląd PDF jest dokładnie tym, co zostanie wysłane.

Status per reklama i alert recydywy po zgłoszeniu.

Eksport JSON / CSV / PDF; STIX 2.1 przechodzi walidację.

Reguły nie da się opublikować bez testu na zbiorze z widocznym FP.

Implementacja: pakiet jest wersjonowany (packages/{id}?v=); submit działa tylko na zamrożonej wersji z hashem treści.
